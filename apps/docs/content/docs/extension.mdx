The extension is a Manifest V3 Chrome extension. There is no Chrome Web Store listing yet (it is tracked in [issue 26](https://github.com/FindMalek/skiffr/issues/26)), so you load it unpacked. It needs Chrome 142 or a Chromium browser of the same age.

## Install

The easy way, step by step with pictures of the clicks in words, is in [install](/docs/install): download `skiffr-extension-vX.Y.Z.zip` from the [latest GitHub release](https://github.com/FindMalek/skiffr/releases/latest), unzip it, and load the folder at `chrome://extensions` with Developer mode on. Your own server also serves the matching zip at `<api>/downloads`, the hosted instance links that page to the GitHub release. An unpacked extension is not updated by Chrome: after a server update download it again, replace the files and press reload on its card.

Or build it from the repo:

```bash
pnpm --filter extension build
```

In `chrome://extensions` turn on developer mode, choose Load unpacked and pick `apps/extension/.output/chrome-mv3`.

Or take a CI build: every pull request uploads `extension-chrome-pr-<number>` and every push to `main` uploads `extension-chrome-latest`, from the [CI runs](https://github.com/FindMalek/skiffr/actions/workflows/ci.yml). GitHub login is required and artifacts expire. Unzip the download, extract the inner `extension-<version>-chrome.zip` into an empty folder and load that folder unpacked.

## Connect it

1. In the dashboard open **Extension**, name the token after the machine and press **Create token**
2. In the extension options (right click the icon, **Options**) set **API url** (`http://localhost:3001` locally, `https://api.skiffr.findmalek.engineer` on the hosted instance) and paste the token in **Token**
3. Press **Test connection**: it says "Connected as" and your name

Save your profile first: a fill without one stops with "No profile saved yet". Save it in the dashboard under Settings, Profile, see [install](/docs/install#connect-it-and-apply).

## Use it

On an application form (Greenhouse, Lever, Ashby, Workable, Workday and other common systems, also inside iframes) a toast asks "Autofill this application?":

- **Yes** fills the form
- **No** closes the toast
- **Don't ask on this site** stops the toast on that site

`Ctrl+Shift+F` (`Cmd+Shift+F` on macOS) fills the current page without the toast. Remap it at `chrome://extensions/shortcuts`.

For each field the extension takes the first answer it has: what you filled on this very form before, then a saved answer for the same question, then a language model that maps the field to a key of your profile. The model needs a provider key on the server, see [environment](/docs/environment): without one a fill fails with "The skiffr server has no AI key yet." Fields the model is unsure about are filled and outlined in amber. An answer from a similar question is never filled by itself, the empty field is outlined as a suggestion. When it is done the toast says how many fields were filled and how many are outlined.

It never submits a form, never clicks submit, next or apply buttons, and never touches password or hidden inputs. You review the form and press the button.

After a fill the extension records what you corrected, cleared or left as filled, when you submit, leave the page or stop editing for 5 minutes (at most 3 batches per session). Sensitive fields are never sent, and forms with more than 60 learnable fields only record the first 60. The details and limits are in [how skiffr learns](/docs/learning). What is sent where is in [privacy](/docs/privacy).
